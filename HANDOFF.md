# Handoff

## What this project is

ProfitPad CRM (working name): an object-based, AI-customizable CRM in the spirit of Foundry/HubSpot. Principles:
- Rock-solid Postgres object model; one real typed column per property.
- Almost all changes are made by AI (or ProfitPad support) under strict rules that the database itself enforces (`meta.*` functions). See `docs/RULES.md`.
- AI reporting gets read-only access to the `reporting` schema.
- Planned: daily AI agents that tune report SQL and calculation SQL (indexes, helper tables), flagging slow ones.
- Long term: one Postgres database per client on shared clusters, one shared app. For now everything is in `profitpad_crm_db` on the current server.

The design applies lessons from a previous HubSpot-to-Postgres mirror: single association table, store each link once, real types, enum metadata in the DB, explicit merges/deletes.

## Structure

- `CLAUDE.md`: entry point, DB connection details and rules
- `AGENTS.md`: agent instructions
- `docs/RULES.md`: rules for changing a tenant (naming, codes, calculations, reporting, destructive actions)
- `docs/architecture.md`: schemas, base columns, object codes, associations, roles, API layout
- `docs/property-types.md`: property types and their options
- `db/bootstrap/000_superuser.sql`: one-time grants, run by n8n (already run on the server); `002_view_reader.sql` creates the custom view query role (run by n8n before migration 0030; not yet run on the server)
- `db/migrations/*.sql`: applied in byte order by `db/migrate.sh`, tracked in `meta.migrations`. Already-applied files are never edited; fixes go in new files (that is why `0004a` and `0009` exist)
- `db/tests/001_core.sql`: SQL assertions; run with `./db/test-local.sh` (throwaway local cluster, never the real DB: tests consume ids)
- `api/`: TypeScript Fastify API (`npm run dev`, `npm run typecheck`, `npm run create-key`)
- `web/`: React + Vite UI (`npm run dev` on :5173, proxies `/v1` to the API on :3000 keeping the browser's Host, so local Google/Microsoft callbacks are `http://localhost:5173/v1/auth/<provider>/callback`; `npm run build`). Inter body font, Montserrat titles, colors from the theme setting
- `docs/deploy.md`: hosting diary of ProfitPad's own server (34.130.249.246; repo github.com/profitpad-inc/profitpad-crm, public). Since 2026-11-08 (section 24) the server runs the published `:main` images from `/opt/profitpad-crm` (install.sh with `PCRM_VERSION=main`, behind the host nginx: web container on 127.0.0.1:8081, 8080 is Foundry/ERPNext; db on 127.0.0.1:5434 for the SSH tunnel). `crm.profitpad.com` serves the UI and the API; `api.crm.profitpad.com` forwards to the same container; `api.test-crm.profitpad.com` redirects to crm. Redeploy: push to main, then `./scripts/deploy.sh` (waits for CI and Images on that commit, runs install.sh on the server, checks every container runs the commit; migrations run on start). The old setup (GitHub Pages, `deploy/docker-compose.yml`, `deploy/db.sh`, `deploy/nginx-*.conf`, `deploy/.env.example`) was removed from the repo 2026-11-08; `/srv/profitpad_crm` on the server is only a checkout now
- `deploy/install/` + `.github/workflows/images.yml`: install from published images (no clone). Five services: `web` (Caddy: HTTPS, the UI and every API path on one address; `web/Dockerfile`, `web/Caddyfile`), `api`, `migrate` (`db/Dockerfile`, `db/entrypoint.sh`: bootstrap + migrations on every `up`, also `add-admin` and `psql`), `db` (stock postgres:15), `renderer` (`deploy/renderer/`). Images `ghcr.io/profitpad-inc/profitpad-crm-{api,web,migrate,renderer}` (public): `:main` on every push to main, `:X.Y.Z`/`:X`/`:latest` plus a GitHub release with `docker-compose.yml` and `install.sh` on a `v*` tag. `install.sh` installs or updates: asks Google/Microsoft/both, picks the next free port when the proxy port is taken, asks for the first admin until one exists (so re-running after a failed start finishes the install); `PCRM_BEHIND_PROXY=<port>` for a server whose own nginx does HTTPS, with `nginx-proxy.conf` as the site
- `scripts/generate_sample_data.py`: creates sample records and associations through the API (made in a forked session; run only against a local copy unless you want sample data in the real DB)
- `api/packages/defense/DEFENSE_HANDOFF.md`: everything about the defense package (data model, the 18 views, AI integrations and n8n workflows, the defense CRM install, how to change and ship the package, what is left). Read it before any defense work. It replaced `defense_crm_handoff.md` (removed 2026-11-22)
- `scripts/seed_defense_data.py`: demo data for a CRM with the `defense` package (32 companies, 127 contacts, 12 defense-pipeline deals, 50 products, 10 quotes with lines, partnerships, OEM integrations, trips, expenses, marketing materials, BOMs with component lines, intel topics, escalations; opportunity sources only if empty). Uses existing users as owners, reuses helpers from generate_sample_data.py. `PCRM_API_URL` defaults to https://crm.defense.profitpad.com; `PCRM_API_KEY` skips the key prompt

## How to start the UI

Run the API (below), then in another terminal: `cd web && npm run dev` and open http://localhost:5173.
